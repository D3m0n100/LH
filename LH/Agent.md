# LH 项目增量协作规则

遵循全局 `AGENTS.md`；以下只定义本项目的额外约束。

## 控制面

1. 主 Agent 是 Supervisor，只负责理解目标、判断、路由、纠偏、验收和最终决策。
2. 真实仓库任务才创建子 Agent；普通问答、方案讨论和不需要仓库操作的任务不创建。
3. Supervisor 不直接修改源码，不代替子 Agent 执行代码定位、实现、审查或运行验证。
4. Supervisor 仅在确有必要时读取少量项目状态、任务摘要和子 Agent 返回证据，不重复执行子 Agent 已完成的工作。
5. 同一任务的继续工作、补充检查或返修优先交回原子 Agent。
6. 只有任务职责发生变化、需要独立上下文或原子 Agent 无法继续时，才创建新的子 Agent。
7. Supervisor 只保留需求、决策、关键证据、子 Agent 摘要和最终结论，避免将完整扫描结果、日志和中间过程带入主线程。

## 路由规则

1. 需要理解代码、定位根因或确定修改范围时，先派 `repo_explorer`。
2. 目标和范围已经明确的代码修改，直接派 `implementer`；不得为了形式重复探索。
3. 非简单修改、跨文件修改、高风险路径或 Supervisor 对结果存在疑问时，派 `reviewer` 独立审查。
4. 存在可执行验证条件时派 `verifier`；当前环境缺少 Qt、CMake、CTest、Windows 或硬件时直接记录“需要运行验证”，不重复探测。
5. 只读任务只有在彼此独立、不会重复扫描且能缩短关键路径时才并行；源码写入始终串行。
6. 不为同一职责重复创建多个 Agent。需要补充信息时优先向原 Agent 追加指令。
7. 独立探索或审查默认使用最小上下文；只有实施者确实需要完整需求历史时才继承更多主线程上下文。
8. 不要求每个任务机械经过所有子 Agent；Supervisor 根据任务性质选择最短正确路径。

## 派发规则

Supervisor 派发任务时，只提供完成当前任务所需的信息：

* 目标；
* 必要背景；
* 允许范围；
* 禁止范围；
* 验收条件；
* 期望返回内容。

不得将与当前任务无关的完整主线程历史传递给子 Agent。

如果目标、范围或验收条件发生变化，由 Supervisor 明确补充或重新派发，子 Agent 不得自行扩大任务。

## 返回规则

子 Agent 返回时只保留 Supervisor 做下一步决策所需的信息：

* 结论；
* 修改文件或检查范围；
* 关键 `file:line` 证据；
* 关键实现、审查或验证结果；
* 未验证项；
* 阻断项；
* 需要 Supervisor 决策的问题。

不得将大段日志、完整扫描过程、完整命令输出或与当前决策无关的上下文回灌给 Supervisor。

## 范围与并发

1. 每批只处理一个明确目标，不顺带重构、重命名、格式化或清理无关代码。
2. 保留用户已有改动、编码、BOM 和行尾。
3. 不得根据整个 `git status` 推断本批修改范围。
4. 同一时间只允许一个源码写入者。
5. 并行仅用于彼此独立、不会重复扫描且不存在写入冲突的任务。
6. 子 Agent 发现必须扩大授权范围时，应停止并报告，由 Supervisor 决定是否重新派发。
7. 多个子 Agent 结果冲突时，由 Supervisor 比较证据并决定下一步。
8. 子 Agent 不得为了处理冲突自行扩大任务范围。

## 审查与验证

1. 独立代码审查与运行验证由 Supervisor 根据任务风险和验收条件决定是否派发。
2. 简单、低风险且结果明确的任务，不要求机械增加额外审查步骤。
3. 非简单修改、跨文件修改、高风险路径或结果存在明显不确定性时，应优先进行独立审查。
4. 存在有效运行环境且任务需要实际行为确认时，应进行运行验证。
5. 当前环境缺少 Qt、CMake、CTest、Windows、硬件、依赖或其他必要条件时，直接记录相应验证未执行。
6. 已确认无法在当前环境执行的验证，不重复探测或反复尝试。

## 返修

1. 审查或验证发现需要修改的问题时，由 Supervisor 退回原 `implementer`。
2. 同一任务返修继续使用原 Agent 上下文，不重新创建新的实施 Agent。
3. 返修完成后，只重新执行受到修改影响的必要审查或验证。
4. 不因一次返修机械重跑全部探索、审查和验证流程。
5. 如果返修需要突破原授权范围，由 Supervisor 重新判断并明确授权。

## 验收

1. Supervisor 根据各子 Agent 返回的代码证据、差异证据、审查结果和实际验证结果进行验收。
2. Supervisor 不通过亲自重新扫描代码、重新实现修改或重复运行验证来代替子 Agent。
3. 未实际执行的验证不得描述为“通过”。
4. 无法执行的验证必须明确标记为“未验证”或“需要运行验证”。
5. 最终结论必须能够由实际证据支持。

验收结论仅为：

* **通过**
* **退回原 Agent 返修**
* **需要用户或外部环境决定**

## 冻结范围

未经用户明确、狭窄授权，不修改：

* `third_party/custom_dsp_language/compile/**`

不得修改构建产物、备份、历史残留或用户已有改动。
