# LH 项目规则

本文件适用于所有在 LH 项目中工作的 Codex Task 和 Subagent。

## 工作原则

- 修改前先检查与当前任务直接相关的现有代码。
- 必要时追踪真实调用链、执行流程和数据流。
- 修复 Bug 前先确认根因，不针对表面现象打补丁。
- 优先依据仓库代码、测试、日志和实际执行结果，不依赖猜测。
- 修改范围保持在当前任务所需的最小正确范围。
- 不进行无关重构、重命名、格式化或清理。
- 保持任务范围外的现有行为不变。

## 保护已有修改

- 保留用户已有的未提交修改。
- 不根据整个 dirty working tree 推断当前任务范围。
- 不覆盖与当前任务无关的本地修改。
- 未经明确授权，不执行 `git reset --hard`、`git clean -fd` 等破坏性操作。
- 除非任务明确要求，否则保留原有编码、BOM 和行尾格式。

## 写入隔离

- 同一个 checkout 同一时间只允许一个写入者。
- 多个 Agent 可以并行读取、分析、Review 和测试。
- 并行修改代码必须使用独立 Git worktree 或其他隔离工作副本。
- 不允许多个 Agent 同时修改同一个 checkout。

## 冻结区域

未经用户明确且具体的授权，不得修改：

- `third_party/custom_dsp_language/compile/**`

该目录仍允许读取、搜索、配置、构建和测试。

## 验证规则

- 每次修改执行能够验证当前变化的最小相关检查。
- 修改共享基础设施、公共接口、CMake、数据库、线程或核心运行路径时，应扩大验证范围。
- 不得为了获得 PASS 而删除、跳过、削弱或绕过测试。
- 无法执行的验证必须明确标记为 `NOT VERIFIED`。
- Qt 兼容性必须保持项目的 Qt 5.15 基线。

macOS、Linux、Windows、GUI/offscreen 和硬件验证必须分别记录。

一个环境中的 PASS 不代表其他环境也已通过。

## Multi-Agent V1 协作

项目使用长期存在的四个 Task：

- Supervisor：负责编排和流程决策。
- Development：负责主要代码修改。
- Review：负责独立代码审查。
- Verification：负责独立构建和测试验证。

需要独立验证时：

- Development 应提供 Base SHA、Candidate SHA、修改文件和相关验证结果。
- Review 和 Verification 应尽量验证同一个 Candidate SHA。
- Task 之间优先传递摘要、证据和 `file:line`，避免重复传递大量源码和日志。
- 只有在并行独立工作或上下文隔离确有价值时才创建额外 Subagent。

每个长期 Task 的具体职责以 `.codex/roles/` 下对应角色文件为准。

发生上下文压缩、恢复会话或角色状态不确定时：

1. 重新读取对应角色文件。
2. 确认当前任务目标。
3. 检查当前 Git 状态和 Candidate SHA。
4. 不仅依赖压缩后的对话摘要继续执行。

## 完成标准

报告任务完成前至少确认：

- 已检查本次任务实际 diff。
- 已列出修改文件。
- 已说明实际执行的构建和测试。
- 已区分 `PASS`、`FAIL` 和 `NOT VERIFIED`。
- 已说明剩余风险、阻断或环境限制。

“代码已经写完”不等于“任务已经验证完成”。
