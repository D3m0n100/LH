# 项目整改协作规则

## 总控与实施

1. 总控负责目标确认、派发、等待、独立验收和结果交接；派发前只读取本文件、相关源码、调用链和测试，并明确目标、授权文件、禁止范围、权衡和验收要求。
2. 代码实施、补测试和自检交给唯一实施子智能体；子智能体运行期间总控只等待，完成后由总控独立验收，不以交接报告代替验收。
3. 不重复扫描全项目，不顺带处理其他批次、无关重构或格式化。

## 子智能体执行

1. 调度参数默认必须显式为模型 `gpt-5.6-luna`、`reasoning_effort: "xhigh"`；无法设置或回执不符时阻断。只有 P0/P1、并发、数据一致性、安全、生命周期和跨模块高风险任务才使用 `max`。
2. 只修改授权文件，保持接口兼容及原编码、BOM、行尾；不得触碰冻结模块、构建产物、历史残留和用户既有改动。
3. 首次只读取授权文件和相关调用链，返修只读取差异；遇到歧义、越权依赖或冲突立即报告。
4. 只做必要自检：范围、直接调用链、已知可用目标测试/静态检查、明显语法错误、冲突标记和未解决问题；不做全项目审查、完整回归或最终业务判断。
5. 当前环境默认静态验收；缺少 Qt、CMake、CTest、Windows 或硬件时直接标记“需要运行验证”，不重复探测。
6. 仅在开始、阻断和完成时汇报；交接只包含完成内容、修改文件、验证结果、未解决问题和需总控决定事项。

## 并行与执行中调整

1. 多个子智能体只可并行进行彼此独立的只读分析，禁止写文件、修改测试或构建配置。
2. 同一批次只允许一个子智能体写共享目录；实施按依赖串行，测试注册、公共 CMake、接口和配置不得并行修改。
3. P0/P1 和数据正确性优先于导出、测试体系和 P3 重构；维护性重构须在回归保护后进行。
4. 补充要求转发给当前实施子智能体；替换方向先停止原任务并确认不再写入；进度询问不改变范围。
5. 返修继续使用原实施子智能体，不另起重复实施任务。

## 总控验收与记录

1. 验收必须覆盖范围/冻结目录、核心问题、失败路径、调用链、回归测试、兼容性和未运行验证；P0/P1、安全、数据丢失、状态错乱和测试可信度不得省略。
2. 结论只能是“静态验收通过，编译与运行测试需要验证”“暂不通过，退回原实施子智能体返修”或“阻断，需要用户选择或外部环境”。
3. 长任务目标、授权范围、关键发现、验证结果和风险通过当前对话、委派说明和交接结果维护；不自动创建、压缩或更新额外规划文件。
