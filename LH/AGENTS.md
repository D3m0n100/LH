# LH 项目增量协作规则

遵循全局 `AGENTS.md`；以下只定义本项目的额外约束。

## 实施与委派

1. 只读检查、文档修改和明确的单文件机械修改由总控直接完成。
2. 非简单代码修改、补测试或跨文件修改交给唯一实施子智能体。
3. 实施子智能体默认显式使用 `gpt-5.6-luna / high`；复杂多文件语义、架构决策或失败路径较多时使用 `xhigh`；仅 P0/P1、数据一致性、数据丢失、安全、并发、生命周期或高风险跨模块任务使用 `max`。无法设置要求的参数时阻断。
4. 派发只需明确目标、授权文件、禁止范围和验收条件。
5. 子智能体只读取授权文件和必要的直接调用链；发现必须越权时停止并报告。
6. 子智能体执行期间总控不重复实施；返修继续使用原子智能体。

## 范围与并发

1. 每批只处理一个明确目标，不顺带重构、格式化或清理无关代码。
2. 同一时间只允许一个写入者。
3. 只读子智能体仅在任务彼此独立、不会重复扫描且确实能缩短关键路径时并行使用。
4. 保留用户已有改动、编码、BOM 和行尾；不得根据整个 `git status` 推断本批修改范围。

## 验收

1. 实施者只做最小相关检查，并报告修改文件、验证结果、未验证项和阻断。
2. 总控只复核本批差异、直接调用链、失败路径和必要测试，不重复全项目扫描。
3. 当前环境默认静态验收；缺少 Qt、CMake、CTest、Windows 或硬件时直接标记“需要运行验证”，不重复探测。
4. 验收结论为：通过、退回原实施者返修，或需要用户/外部环境决定。

## 冻结范围

未经用户明确、狭窄授权，不修改：

- `src/compiler/**`
- `third_party/custom_dsp_language/compile/**`

不得修改构建产物、备份、历史残留或用户已有改动。
