# LH 项目增量协作规则

遵循全局 `AGENTS.md`；以下只定义本项目额外约束。

## 实施与委派

1. 总控负责理解目标、维护全局上下文、确定范围和最终验收。
2. 小范围修改、强依赖当前上下文的修改、文档和只读检查由总控直接完成。
3. 仅当任务可独立描述、上下文集中且实施工作量足够大时，才交给实施子智能体；不得仅因跨文件或任务复杂而委派。
4. 实施子智能体默认使用 `gpt-5.6-luna / medium`；复杂语义、失败路径较多或高风险任务使用 `max`。
5. 如果委派需要重复大量主线程上下文，则优先由总控直接完成。

## 子智能体生命周期

1. 同一总控会话、同一项目默认只维护一个实施子智能体。
2. 首次真正需要委派时才创建；后续相关任务和返修继续复用原子智能体。
3. 不得仅因开始新任务、修改不同文件或上一批完成而创建新子智能体。
4. 只有原子智能体失效、上下文明显污染、严重 context fatigue、项目实质切换或执行环境不匹配时才允许重建。
5. 复用子智能体不代表继承授权；每批必须重新明确目标、授权文件、禁止范围和验收条件。

## 上下文与范围

1. 派发只提供当前任务所需的最小增量上下文，不复制完整主线程历史。
2. 子智能体只读取授权文件及必要的直接调用链；必须越权时停止并报告。
3. 每批只处理一个明确目标，不顺带重构、格式化或清理无关代码。
4. 保留用户已有改动、编码、BOM 和行尾；不得根据整个 `git status` 推断本批范围。

## 写入与验证

1. 同一时间只允许一个写入者；子智能体实施期间总控不重复修改同一目标。
2. 实施者执行最小相关验证，并报告修改文件、验证结果、未验证项和阻断。
3. 总控只复核本批差异、直接调用链、关键失败路径和必要测试，不重复全项目扫描。
4. 当前环境默认静态验收；缺少 Qt、CMake、CTest、Windows 或硬件环境时标记“需要运行验证”，不重复探测。

## 冻结范围

以下是源码写入冻结区，不是构建排除区：

- `src/compiler/**`
- `third_party/custom_dsp_language/compile/**`

未经用户明确且狭窄授权，不得修改上述目录源码。云端或本地完整项目 configure/build/CTest 必须允许读取并编译这些目录；不得手动修改构建产物、备份、历史残留或用户已有改动。
