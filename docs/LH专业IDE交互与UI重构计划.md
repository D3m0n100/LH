# LH 专业 IDE 交互与 UI 重构计划

版本：V2.0，2026-10-24。状态：根据调研完善的设计与实施计划；尚未实施本计划中的代码改造，视觉原型待制作与评审。

适用工作区：`D:\Table\LH`。前置资料：`review_execution/ide-ui-research-2026-10-24/UI设计方案与Skills调研.md`。本计划整合前期方向与调研结果，作为后续设计、开发和验收的统一依据。

## 1. 产品目标与范围

将 LH 建设为以编程为主、兼顾设备联调的工业 IDE：工程、文档、构建入口和设备目标关系清楚；日常操作路径稳定；代码、监控和诊断可以在同一工作台连续完成；浅深主题、键盘、DPI 和错误恢复保持一致。

### 已确认的产品决策

| 决策 | 本计划中的落实 |
|---|---|
| 编程为主，兼顾联调 | 默认编程布局；联调布局扩大监控和设备内容，复用同一工程与运行上下文 |
| 统一 IDE 主窗口 | 用稳定工作台容纳代码、监控、设备内容；移除顶层“编程/监控/设备”与内部文档标签叠加的导航结构 |
| 浅色默认、深色可选 | 新用户默认浅色；已有明确主题偏好继续保留；主题、密度与编辑器字体分别设置 |
| 真正多 LH 文档 | 每个文件独立缓冲区、修改态、撤销栈、光标和滚动位置 |
| 工程全文搜索 | 可取消的异步搜索，优先使用未保存缓冲区；结果可定位，明确忽略项与截断 |
| 对齐 LM 功能而非复制旧产品 | 保留 LH 工程格式；不新增 LM 旧项目迁移能力 |

技术基础保持 Qt 5.15.2 / Qt Widgets / 现有 MinGW 构建链。编译器语义、产物 ABI、下载协议和真实控制器缺陷不纳入本轮修复；可以重构其界面入口、状态和诊断呈现，但继续调用原有契约与校验。

本轮不新增语言服务器、终端、插件市场、源码级单步/调用栈、分屏编辑、工程批量替换等独立能力。既有图形组态、函数库拖入、PID 调参、历史查询、导出、通信与 OPC 入口必须在新工作台保留可达路径，按现有能力验收。新增外部依赖不是前提。

## 2. 当前实现与重构重点

以下为本次源码核对结果，静态事实不代表运行时验收：

| 当前实现 | 重构要求 |
|---|---|
| MainWindowUi.cpp 创建顶层编程/监控/设备标签，编程页又包含 Tabbed QMdiArea | 收敛为一层内容标签；侧栏、工具区与布局预设各有独立职责 |

| ProjectController 持有单一 DslScriptEditor 指针 | 将工程元数据与具体编辑器生命周期解耦，保存和构建按文档身份取数据 |
| 已有 ThemeManager 浅深主题，但 MainWindowUi 等位置仍有局部样式 | 汇总样式清单，建立共享语义令牌与组件状态规范 |

| 已有布局保存恢复；CURRENT_LAYOUT_VERSION 为 1 | 新结构提升布局版本；旧配置可回退默认布局，保留非布局偏好 |

实施前建立“旧入口 → 新入口 → 后端命令 → 回归用例”清单，覆盖菜单、快捷键、工具栏和上下文菜单。找不到替代入口的功能不得随布局调整删除。

### 各区域职责

- 主菜单：完整功能入口，菜单与快捷键共用命令。
- 主工具栏：稳定呈现工程、构建入口、目标及少量高频全局命令。窄窗口先压缩次要文字，再进入溢出菜单；工程/入口/目标的完整信息仍可查看。
- 导航与侧栏：项目、搜索、函数库及相关工具；导航切换只改变侧栏内容，不改变工程与运行状态。使用图标、提示及可访问名称，支持键盘访问。
- 内容区：统一管理代码、监控、设备、诊断等内容身份。代码是文档；监控/设备是既有服务的视图，不能在关闭或重建视图时隐式销毁后台服务。
- 对象属性：仅呈现当前选择对象的可编辑属性；无上下文时收起或显示简洁说明。连接摘要和全局任务不重复堆在属性区。
- 底部工具区：问题、构建、通信、调试；有来源、时间、筛选、复制和清除策略。日志缓冲有上限，尊重用户暂停自动滚动的选择。
- 状态栏：只提供摘要与明确入口；正常状态克制，错误使用图标和文字，不靠大面积状态色表达。

提供“编程”“联调”两种默认布局。布局切换只改变面板可见性、尺寸和位置；切换或关闭内容视图不自动连接、运行、下载或停止采集。若活动采集视图被关闭，后台继续时必须保留可见状态与停止入口。

## 5. 设计系统与组件规范

### 令牌分层

| 层次 | 内容 | Qt 映射 |
|---|---|---|
| 基础 | 色阶、字体、间距、图标尺寸、边界宽度 | C++ 集中定义，不散落硬编码 |
| 语义 | 主/次文本、窗口/内容/输入背景、边界、焦点、选中、禁用、警告/错误/成功 | QPalette 与 ThemeTokens 等统一接口 |
| 组件 | 标签、工具按钮、树/表、输入、停靠标题、通知、图表 | 共享控件规则与必要 QSS；自绘控件读取同一令牌 |

视觉方向采用克制的桌面工具风格：内容区域层次清晰、细边界、少量强调色、统一线性图标；避免大量卡片、阴影和装饰性渐变。保留 Windows 原生窗口行为。

字体区分界面中文与代码等宽字体，检查缺字及中英文混排；编辑器字体单独缩放。间距以 4/8 等一致尺度作为起点，紧凑/舒适两种密度在原型中校准后确定默认值，不硬套网页 16px 和触屏 44px。所有布局使用逻辑尺寸并允许合理拉伸、折叠和溢出。

组件规范覆盖 default、hover、pressed、focused、selected、disabled、busy、error 等适用状态。普通文本对比度以 4.5:1、大文本及关键非文本边界以 3:1 作为设计检查目标；不据此直接宣称整套桌面软件符合某项无障碍认证。焦点必须可见，错误与状态同时提供文字或图标。主题切换覆盖编辑器、语法色、曲线、图例、坐标轴、工具提示及原生弹窗。

### 设计阶段交付物

1. 设计简报与区域职责图。
2. 颜色、字体、间距、密度、图标、焦点规范。
3. 高频组件状态样张及文案规范。
4. 真实内容原型：2–3 个同架构布局草案，比较编辑空间、命令可发现性和联调切换；选定后制作浅深主题及窄窗口样张。
5. 关键交互流程图与命令/状态矩阵。

原型使用真实 LH 工程路径、代码、中文变量名、长错误文本、监控通道和离线场景。不得用占位内容掩盖密度问题。设计评审决定布局和视觉细节，不重复询问已确认的产品方向。

## 6. 文档、工程与构建模型

### 独立文档管理

每份文档拥有稳定 documentId、规范化路径、类型、缓冲区、修改态、版本、只读原因、光标与视口状态。Windows 路径大小写和等价路径按现有身份规则去重；新建未落盘文件使用临时身份，另存为处理冲突。同名文件以必要的父路径区分。

每个 LH 文件创建独立 DslScriptEditor，既有补全、函数库拖入、组态等能力跟随正确文档。切换活动文档时，属性、项目定位、状态栏等只绑定一次；关闭后不得残留信号连接或悬空指针。编辑器组件自身嵌套的导航同步审查，消除同义标签，但保留确有职责的源代码/组态等视图。

标签支持激活、修改标记、重排、关闭、关闭其他、关闭全部及 MRU 切换。恢复会话仅恢复已落盘文件和视图位置，未保存内容不虚假承诺崩溃恢复能力；异常退出恢复若现有机制不支持，明确列为后续独立能力。

### 保存、关闭与外部修改

- 保存：只保存当前文档；保存全部：协调所有可保存文档和工程元数据。文件保存成功与工程保存成功分别记录，不伪造跨文件原子事务。
- 关闭工程/退出：统一收集未保存项，用户选择保存、放弃或取消；保存失败则保留相关缓冲区并中止关闭，不因其他文件已保存而清空状态。
- 外部修改：干净文档可提示重新载入；脏文档必须明确冲突，禁止静默覆盖。外部删除、重命名、权限变化保留缓冲区并提供另存为路径。
- 使用已有安全写入及编码规则；改造不得静默改变编码或换行方式，不能可靠回写时明确提示。
- 生成物默认只读，展示来源和生成时间；另存副本与编辑工程源码有清楚区别。
- 项目树删除/重命名和编辑器状态统一协调，取消时不改变文档身份；工程外文件显式标识，不因打开而自动加入工程。

### 构建入口独立

活动文档、工程文件成员、构建入口、目标配置是不同概念。打开 A.lh/B.lh、搜索跳转或查看生成物不改变构建入口。入口由显式“设为构建入口”动作修改，工具栏始终可查看其完整身份。

默认构建流程：校验工程及入口 → 检查工程内待构建修改 → 明确保存并构建或取消 → 对保存后的输入记录会话、文件版本和配置 → 调用现有 BuildController。工程外文档不进入构建输入。构建期间的输入修改应使旧结果明确过期，并继续执行既有产物发布/下载校验。

编译器错误映射、generation/session 过滤、取消及 compileOnly 校验保持原契约；多文档 UI 必须提供准确的文件与版本信息，无法可靠映射时显示诊断而不猜测源码位置。

## 7. 搜索、命令与运行状态

### 工程全文搜索

首版提供文字搜索、区分大小写、整词及包含/排除路径；正则和批量替换暂缓。Ctrl+F 为当前文档查找，Ctrl+Shift+F 为工程搜索；Ctrl+P 快速打开，Ctrl+Shift+P 命令面板，Ctrl+G 行跳转。其余快捷键先清查冲突，再复用已有约定。

搜索使用可取消后台任务；输入防抖，结果分批交付，项目切换/新查询/关闭搜索时取消并通过查询代次与工程会话过滤旧结果。禁止工作线程访问 QWidget。默认范围为工程内可支持的文本，优先读取打开的缓冲区快照并标识未保存来源。

跳过二进制、版本库、构建/缓存、生成输出；复用可信路径判断，不沿符号链接或 reparse point 扫描到工程外。默认上限：单文件 2 MiB、5000 个文件、20000 条结果；达到限制或遇权限/编码问题时显示具体忽略或截断原因，禁止把部分结果标为完整搜索。

结果按文件分组显示行号和上下文，键盘可选中并跳转。跳转前核对文档版本；内容已变化时重新定位或提示结果失效，不能跳到错误行后假装准确。项目扫描规则与快速打开共享基础能力，但全文搜索结果与查询生命周期独立。

### 统一命令状态

为命令定义稳定 ID、名称、快捷键、适用上下文、执行入口、enabled/checked/busy 和不可用原因。菜单、主工具栏、命令面板及合理局部入口共用状态；同一后端动作只触发一次。

全局构建/下载/运行与曲线区开始采集/暂停显示是不同命令，文案要表达对象，避免都写“开始/停止”。命令面板保留不可用项及原因，禁用控件可通过附近说明或帮助入口解释，不能只依赖无法触发的工具提示。

不新造一个与既有服务竞争的总状态机。工程、构建、连接、运行和监控分别从已有控制器读取事实，由 UI 层计算命令可用性。构建是独立状态；compileOnly 是产物能力标记；连接状态不能代替产物有效性。

| 场景 | UI 要求 |
|---|---|
| 无工程 | 提供新建/打开/最近工程，构建等命令解释缺少的前置条件 |
| 构建中 / 取消中 | 显示入口和任务阶段；禁止重复构建；只提供真实可用的取消，不编造 ETA |
| 构建失败 / 已过期 | 问题与原始输出可达；过期结果可见但不充当当前有效产物 |
| 离线编译成功 | 明示仅编译产物，下载由现有校验拒绝并解释原因 |
| 目标缺失 / 未连接 | 运行和下载按各自契约禁用；引导到相应配置或连接步骤 |
| 连接中 / 失败 / 中断 | 显示进行中状态、具体原因、最后更新时间及可用恢复动作 |
| 空闲 / 运行 / 暂停 | 来源为真实会话能力；不支持的源码级调试不显示为可用功能 |
| 监控无数据 / 坏质量 | 区分未开始、等待样本、数据过期、通道错误；不可用值不显示成正常 0 |

## 8. 设备、监控与反馈

### 设备内容

按“目标与配置 → 连接 → 产物 → 下载/运行 → 诊断”组织信息。明确显示目标身份、连接摘要、构建入口、产物新旧与能力、最近操作结果；详细参数按需展开。长任务显示阶段与可用操作，错误给出可复制信息及下一步。

切换内容标签或选择目标不隐式连接/下载/运行。目标修改、项目切换和活动任务的冲突继续由现有业务层拒绝或协调。连接状态未知就显示未知，不用历史成功状态代替当前事实。

### 监控内容

中央曲线优先，通道配置、观察值、统计和参数按需展开。区分采集控制、图表视口、历史查询、日志记录与导出；暂停绘图不声称后台采集已停止。曲线、图例、表格和通道选择互相定位，数据时间、单位和质量一致。

参数编辑区分当前回读值、待提交值、提交中、成功待回读、回读确认、失败/超时。批量操作沿用既有事务与失败语义，不在 UI 中假造成功。PID 调参保留完整入口；实际设备行为仍待相应控制器验收。

### 问题与通知

构建错误优先进入问题列表并提供定位；完整输出保留。非阻塞反馈用状态或内联说明，弹窗用于必须决策和无法继续的失败。连接抖动、重复告警按来源聚合，不连续抢焦点。问题列表筛选、定位和计数关联同一次有效构建。

## 9. 技术拆分、迁移与边界

建议职责命名，实施时允许复用等价现有类，避免为了分层增加空壳：

| 职责 | 处理方式 |
|---|---|
| DocumentManager / 文档适配器 | 文档集合、身份、生命周期、保存协调与版本；替代单 m_dslEditor 假设 |
| ProjectController / ProjectCommandCoordinator | 工程元数据和操作协调；不拥有具体编辑器；以文档服务端口获取需要的数据 |
| 工作台与内容管理 | MainWindow 保持组装；导航、内容激活、属性与焦点路由清晰分离 |
| CommandRegistry / 上下文适配 | 复用 QAction 及真实控制器状态；不复制后端状态机 |
| ProjectSearchService | 后台文本扫描、代次取消、过滤和限额；通过模型交付结果 |
| ThemeManager / ThemeTokens | 两主题、密度和组件样式集中管理 |
| SettingsController / 布局管理 | 稳定 objectName、新布局版本、预设、恢复与重置 |

优先使用原生 QMainWindow、QDockWidget、QToolBar 和文档标签容器；中央不再保留与统一文档标签重复的 MDI 导航。Qt Advanced Docking System / KDDockWidgets 仅在原生方案存在明确缺口后，单独验证固定版本、工具链、布局迁移与许可条件，再决定是否引入。

旧布局版本 1 不强行解析为新结构；保留旧值以便诊断，首次进入新版本使用默认布局并说明可重置。主题、字体、最近工程等非布局偏好保留。恢复状态不合法或屏幕不存在时，窗口与面板回到可见区域。新布局记录不得覆盖旧版本命名空间。

迁移采用单一路径：先验证文档服务与现有控制器适配，再替换工作台。过渡兼容层只允许短期存在，交付前移除“单编辑器”和“文档集合”并行写状态的路径。保留既有未提交修改和历史验收证据；按明确文件范围记录每阶段改动，不自动提交或推送。

## 10. 实施阶段与交付门槛

| 阶段 | 任务与交付 | 阶段完成条件 |
|---|---|---|
| P0 基线与设计契约 | 旧新入口清单；现有测试/截图基线；组件、命令、状态清单；Qt 5 适配规则 | 既有能力都有归属，已知失败单独登记；范围和设计依据可追溯 |
| P1 设计系统与原型 | 令牌和组件状态；2–3 布局草案；关键流程、浅深主题、窄窗口与密度样张 | 选择统一视觉方向；任务流程无缺口；尺寸依据真实内容确认 |
| P2 文档与上下文 | 独立 LH 文档；保存/关闭/冲突；工程入口分离；诊断按文档和版本导航 | A/B 文档修改与撤销互不污染，打开文件不改变入口；失败不丢缓冲区 |
| P3 统一工作台 | 导航、内容标签、侧栏、属性与底部面板；布局预设、主题、设置迁移 | 一层主内容导航；旧功能入口可达；布局切换无业务副作用 |
| P4 命令与搜索 | 统一命令状态；禁用原因；全文搜索、取消、限额、键盘定位 | 不重复触发；旧查询不串工程；截断明确；结果版本安全 |
| P5 联调与反馈 | 设备层级、监控区、读写反馈、问题/输出/通知；剩余旧样式收敛 | 数据与操作对象清楚；既有后端能力正确呈现；主题覆盖完整 |
| P6 综合验收 | 原生操作、键盘、DPI、可访问性、回归、安装启动；证据与缺陷关闭表 | 本轮必须项全部通过；延期范围与验证限制明确；形成验收记录 |

顺序依赖：P0 → P1 → P2 → P3 → P4 → P5 → P6。每阶段先达到自身门槛再进入依赖阶段。P0 需重新运行基线，不能把以前的测试数字当作本次完成证据。本计划只定义阶段，不在缺少代码工作量基线时承诺工期。

## 11. 验收清单与证据

每项记录版本、环境、步骤、期望/实际、证据路径与结论。状态使用“待实施 / 已实现待验收 / 通过 / 失败 / 延期”，延期必须注明既定范围或明确决策，不能自动记为通过。

| ID | 必须验收内容 |
|---|---|
| UI-01 | 工程打开、新建、最近工程、只读/无效路径反馈；所有旧功能有新入口 |
| UI-02 | 同时打开至少 3 个 LH 文件，独立修改、撤销、光标与滚动；同名/等价路径不误开、不覆盖 |
| UI-03 | 保存当前、保存全部、关闭单项/其他/全部/工程/退出；取消和保存失败均不丢缓冲区 |
| UI-04 | 外部修改/删除/重命名、只读、权限失败、另存冲突；编码与换行遵循既有策略 |
| UI-05 | 打开、搜索跳转及切换标签均不改变构建入口；构建输入与工具栏一致 |
| UI-06 | 构建成功/失败/取消、旧回调、输入变化；诊断只在可靠版本映射下跳转；compileOnly 下载校验不退化 |
| UI-07 | 工程全文搜索包含未保存缓冲区；过滤、大小写/整词、限额、权限/编码忽略、取消和旧结果隔离正确 |
| UI-08 | 菜单、快捷键、命令面板及工具栏共用状态；无快捷键歧义；单次操作只触发一次后端调用 |
| UI-09 | 设备未配置、断开、连接中、失败、中断等状态真实；无硬件环境使用可控替身并明确证据边界 |
| UI-10 | 监控通道、质量/时间、无数据、历史、记录、导出、参数编辑及 PID 入口完整；视图关闭不隐式改变采集 |
| UI-11 | 浅深主题覆盖所有页面与弹窗，无关键硬编码颜色遗漏；图表、焦点、禁用与选中状态可辨 |
| UI-12 | 编程/联调预设、停靠、显示隐藏、重置、重启恢复；旧/损坏布局和多屏移除能恢复可见界面 |
| UI-13 | 仅键盘完成打开工程→文档编辑→搜索→构建→错误定位→保存关闭；焦点顺序与返回位置合理 |

| UI-15 | 安装布局检查和安装目录启动通过；离开源码工作目录仍能加载资源和运行所需组件 |
| UI-16 | 现有必需测试与新增回归全部有最终结果；不明失败不能靠一次重跑掩盖 |

### 显示与响应性矩阵

以 1280×720、1366×768、1920×1080 作为主要窗口检查点，结合 100%/125%/150%/200% DPI，覆盖浅深主题、中文长路径、较大字体、空工程与高密度数据。按 DPI 后可用逻辑空间判断布局，不能要求所有物理分辨率/DPI 组合都保持完整面板；低于支持空间时允许工具区收起并保证命令可达，明确最小尺寸。

多屏不同 DPI 移动、最大化/还原及外接屏移除作为独立检查。记录物理分辨率、DPI 和实际可用窗口区域，不能只写“1080p 通过”。

性能先在 P0 记录固定机器/样本的基线，P1 确定正式预算：编辑和切换不出现可感知阻塞；长任务立即反馈；搜索开始、取消及关闭不等待整次磁盘扫描；监控运行时工程导航、滚动和停止入口仍响应。建议 UI 事件停顿 100ms、取消反馈 200ms 作为调查阈值，不在没有测量时宣称达到。搜索硬限额必须遵守；日志、结果模型和后台任务具有内存与生命周期边界。

### 自动化与人工分工

自动化集中在会造成数据丢失或状态错误的路径：文档身份/生命周期、保存失败、入口分离、搜索取消与旧结果过滤、命令可用性、布局版本和设备调用次数。复用 MainWindowIntegrationTest、DesignerP1RobustnessTest、ProjectSaveCloseTest、DslScriptEditorSaveTest、LmParitySoftwareTest 等既有相关覆盖；新增专门用例按实际测试注册名接入。避免仅断言某个控件存在的实现镜像测试。

视觉、真实键盘、DPI、多屏、辅助技术和安装后窗口操作在原生 Windows 环境检查。已知 offscreen/minimal 与原生 QMessageBox 路径差异不能通过降低产品校验绕过。物理控制器、长稳和故障注入未具备环境时明确未验证，不折算为软件验收通过。

交付证据放在新的 `review_execution/ide-ui-rework-<日期>/`：需求/用例映射、环境与版本、测试完整结果、原生截图和操作记录、缺陷清单、关闭依据与延期项。历史审计、调研和修复目录保持原样。

## 12. 主要风险与处置

| 风险 | 处置 |
|---|---|
| 单编辑器假设散落在工程/保存/构建/属性回调 | P2 逐一列出并替换；以多文档独立性和入口不变作为闸门 |
| 多窗口/标签重建后信号重复或对象悬空 | 明确 QObject 所有权、生命周期和连接管理；验证关闭重开与切换项目 |
| 布局恢复导致不可见工具窗或错误状态 | 新布局版本、稳定名称、失败回退、屏幕边界检查与一键重置 |
| 新样式与既有控件/图表冲突 | 令牌集中，逐控件覆盖；浅深主题和 DPI 同时验收 |
| 命令去重误删合法局部动作 | 分清操作对象，统一执行和状态而非机械删除入口 |
| 原型效果被误当成功能验收 | 设计证据、原生交互证据、后端/控制器证据分别记录 |
| UI 重构扩张为后端重写 | 构建、会话、监控服务复用；涉及编译器/真实硬件的新缺陷单列，不顺带修改 |

计划完成标准：P0–P6 的交付和必须验收项逐项闭环，提供清晰的范围与证据；“设计定稿”“代码已实现”“本地软件验收通过”“真实控制器验收”分别表述，不互相替代。
